## 1. 产品概述

### 1.1 背景与定位

MiniMax H3 是 MiniMax 于 2026-08-03 开源的通用全模态视频生成模型：统一理解文本 / 图像 / 视频 / 音频组成的多模态上下文，可生成带原生立体声音频的视频（最长 15s、最高 2K、24fps、32kHz 立体声）。开源部分为 **H3-Base**（本地推理），**H3-Context-IR** 与 **H3-Regenerate-2K** 暂未开源、仅提供官方 API。

本产品是一个面向开发者的**时间线工作台** Web 工具：以多镜头时间线编排视频项目，输入提示词 / 参数 / 参考素材，逐镜头调用本地 H3-Base 推理服务生成视频并预览成片。结构为「顶部胶片时间线 + 中央舞台预览 + 右侧镜头参数 + 底部提示词坞」，与兄弟项目（Image_MultiModel / SeedVR2 / TTS_MultiModel）的纵向卡片布局明确区分。

### 1.2 目标用户

- 开发者 / 技术创作者：本地跑模型、批量出片
- 产品与内容用户：分镜预演、品牌物料、短视频小样

### 1.3 产品目标与成功指标

- **目标**：让本地 H3-Base 生成能力可被低门槛、多镜头、可复用地使用。
- **成功指标**：单镜头从提交到结果回填的完整闭环可用；历史镜头可回看复用；多项目可切换不串数据。

### 1.4 兄弟项目一致性

- 沿用家族惯例：浅色默认 + 每产品独立强调色，`--seed` 令牌体系；本项目强调色随展示壳模式切换：剧场红 `#b3261e` / 电视琉珀 `#b07612` / 放映机青绿 `#1d7873`，暗色主题下调亮，支持明暗双主题。
- 后端配置与启动脚本风格向兄弟项目（Image_MultiModel 等）对齐。

## 2. 产品范围

### 2.1 In Scope（本期实现）

1. **多项目管理**：项目列表（新建 / 重命名 / 删除 / 切换），项目含镜头集合与参数。
2. **时间线工作台**：顶栏、胶片时间线（镜头段 / 播放头 / 刻度尺 / 加镜头）、中央舞台、右侧镜头参数、底部提示词坞、状态栏、队列浮标。
3. **镜头参数**：模式（文生 / 首帧 / 末帧 / 首尾帧 / 多模态参考）、画面比例、分辨率（768P / 2K 可选）、时长（4/8/10/15s）、输出规格（24fps / 32kHz 立体声）、运镜、风格、2K 重绘开关、衔接。
4. **参考素材**：多模态参考（图 ≤9 / 视频 ≤3 / 音频 ≤3，混合 ≤12），上传与预览。
5. **生成与队列**：提交任务 → 本地推理服务执行 → 队列状态流转（pending / processing / completed / failed）。
6. **历史库**：已生成镜头结果集中回看、预览、复用参数与提示词。
7. **明暗双主题 + 响应式 + 可访问性**。
8. **本地推理接入**：H3-Base（FL2VA + Ref2VA）本地服务，768P 全本地闭环。

### 2.2 Out of Scope（本期不实现）

- **导出 / 分享 / 发布**：暂不做结果导出下载管理与对外分享（预留扩展点）。
- **账号与鉴权**：单机本地工具，无鉴权。
- **H3-Context-IR 官方托管版 / H3-Regenerate-2K（2K）**：两者未开源、仅官方 API。本期本地不自建完整版，2K 仅在前端作为可选能力占位（见 §7.5 边界）。
- **云 API 混用**：本期不做云端 Fallback 切换（见 §7.5，预留配置位）。

> 原则：严格按本 PRD 与现有设计计划实现，不实现文档之外的功能。

## 3. 用户与核心场景

### 3.1 核心用户旅程

```
新建/打开项目 → 在时间线编排 N 个镜头 → 点镜头段 → 编辑提示词/参数/参考素材
→ 生成当前镜头 → 队列执行（本地推理）→ 结果帧回填舞台 → 历史库回看 → 切项目继续
```

### 3.2 关键用例

| ID | 用例 | 说明 |
|---|---|---|
| UC-1 | 多项目切换 | 项目列表不串数据，镜头/参数/历史按项目隔离 |
| UC-2 | 镜头编排 | 添加镜头、切换镜头、按时长显示段宽、总时长联动 |
| UC-3 | 五模式生成 | 文生 / 首帧 / 末帧 / 首尾帧 / 多模态参考 |
| UC-4 | 参考素材上传 | 图/视频/音频混合 ≤12 项，超限与搭配校验（音频须配图或视频） |
| UC-5 | 异步生成 | 提交 → 队列 → 轮询 → 结果帧回填 |
| UC-6 | 历史回看 | 已完成镜头在历史库预览、一键复用参数/提示词重新生成 |

## 4. 功能需求

### 4.1 前端工作台（以现有 index.html 线框为基础升级）

| 模块 | 需求 | 验收要点 |
|---|---|---|
| 顶栏 | Logo、产品名、项目名（可切换项目）、主题 / 帮助 / 分享（占位） / 头像 | 项目名可交互切换 |
| 胶片时间线 | 播放控制、播放头、镜头段（缩略帧/编号/时长/名称）、加镜头、刻度尺 | 点击切换联动舞台与提示词；段宽按时长成比例 |
| 中央舞台 | 16:9 预览（生成结果帧 / CSS 模拟帧过渡）、REC/镜头/时间码、播放条 | 结果帧回填；播放条播放结果 |
| 镜头参数 | 模式/比例/分辨率/时长/规格/运镜/风格/2K 重绘/衔接 | 与真实模型规格对齐；与当前镜头联动 |
| 参考素材 | 上传图/视频/音频、计数、格式与尺寸校验 | 上限校验、混合 ≤12、音频须配图或视频 |
| 提示词坞 | 提示词输入、实时计数、负向提示词（或 Context-IR 优化入口）、生成按钮、预设标签 | 生成按钮发起真实任务 |
| 队列 | 队列浮标、任务状态流转、失败原因透传 | 状态真实反映后端 |
| 历史库 | 结果列表、预览、复用 | 按项目隔离 |
| 多项目 | 项目列表 / 新建 / 重命名 / 删除 / 切换 | 数据隔离 |

### 4.2 后端（FastAPI + 任务队列）

| 模块 | 需求 |
|---|---|
| 生成 API | 接收生成请求（模式 + 提示词 + 参数 + 参考素材），创建任务并返回 task_id |
| 任务队列 | 单机串行/受限并发执行，状态机 pending → processing → completed/failed，超时与重试，失败原因记录 |
| 存储 | 项目 / 镜头 / 任务 / 资产（结果视频）落盘；SQLite + 文件目录 |
| 媒体服务 | 结果视频静态托管、下载、缩略帧提取 |
| 推理客户端 | 对接本地 H3-Base 推理服务（见 §7） |
| 配置管理 | 模型路径、推理服务地址、端口、量化档位、最大并发等统一配置（与兄弟项目对齐） |

### 4.3 数据模型（草案）

```
Project(id, name, created_at, updated_at)
Shot(id, project_id, order, name, prompt, mode, params, duration, aspect, refs[], status, result_asset_id)
GenerationTask(id, shot_id, mode, payload, status, progress, error, created_at, finished_at, result_asset_id)
Asset(id, kind[image|video|audio|result], path, mime, size, meta)
```

## 5. 技术架构

```
┌────────────────────────── 浏览器（index.html）──────────────────────────┐
│  时间线工作台 · 舞台预览 · 参数面板 · 提示词坞 · 历史库 · 项目切换       │
└───────────────┬────────────────────────────────────────────────────────┘
                │ HTTP/JSON (fetch)
┌───────────────▼───────────────┐   ┌───────────────────────────────────┐
│  FastAPI 后端                  │   │   任务队列 Worker（进程内/子进程）   │
│  · 项目/镜头/历史 CRUD         │──▶│   · 状态机 · 并发控制 · 重试/超时   │
│  · 生成任务提交与轮询          │   │   · 推理客户端（diffusers/HTTP）     │
│  · 参考素材上传存储            │   └───────────────┬───────────────────┘
│  · 结果媒体静态服务            │                   │
└───────────────┬───────────────┘   ┌───────────────▼───────────────────┐
                │                   │  本地 H3-Base 推理服务               │
                │                   │  FL2VA(t2va/fl2va) · Ref2VA          │
                │                   │  (768p · 4-15s · 24fps · 32kHz)      │
                └── SQLite + assets/ ─ 存储层 ─────────────────────────────┘
```

- **数据流**：前端提交生成 → 后端落库建任务 → 队列 Worker 调本地推理 → 结果写 assets/ 与资产记录 → 前端轮询状态 → 结果帧回填舞台 + 写入历史库。
- **技术选型**：后端 FastAPI + SQLite + asyncio/线程池队列；前端维持单 HTML（无框架构建链）；推理层优先 diffusers 或 ComfyUI API。

## 6. 推理接入层（本地 H3-Base）

### 6.1 能力边界（依据官方规格）

| 项 | 本地 H3-Base 支持 |
|---|---|
| 检查点 | H3-Base FL2VA（文生 + 首/尾帧）、H3-Base Ref2VA（多模态参考） |
| 分辨率 | 768p（短边），2K 需 Regenerate-2K（未开源） |
| 时长 | 4–15s（整数） |
| 宽高比 | 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 |
| 帧率 / 音频 | 24 FPS / 32kHz 立体声（音画一体输出） |
| Ref2VA 上限 | 图 ≤9；视频 ≤3（每段 2–15s，总 ≤15s）；音频 ≤3（每段 2–15s，总 ≤15s，须配图或视频）；混合 ≤12 |
| 输入格式 | 视频 H.264/H.265（音轨 AAC/MP3）；图 JPG/JPEG/PNG/WEBP/HEIC/HEIF；音频 WAV/MP3 |
| 提示词 | ≤7000 字符 |

### 6.2 推理框架选型（候选，落地时择优）

| 框架 | 说明 | 适用 |
|---|---|---|
| diffusers (ModularPipeline) | 官方集成，`MiniMaxAI/MiniMax-H3`，t2va/fl2va 与 ref2va 双 blockset | 后端进程内直接推理 |
| ComfyUI | 社区推荐工作流，显存调度友好 | 交互式 / 已部署环境 |
| SGLang / llama.cpp(GGUF) | 服务化 / 量化 | 高吞吐 / 低显存 |

### 6.3 硬件与量化（决策参考）

- **24G 显存（4090）+ 64G 内存**：可跑满开源能力（社区蒸馏 INT8 优先）。
- **16G 显存（4080S）**：GGUF-Q4_K_M / INT4，5–7s 稳定，长视频易 OOM。
- 原版 BF16 权重家用卡无法加载，落地时按实际显卡选量化档位并写入统一配置。

### 6.4 Context-IR 的处理（关键边界）

- **现状**：官方 H3-Context-IR 为托管服务，未开源、仅 API；官方建议接入以提升复杂指令质量，或参照官方「视频提示词写作指南」自建简易预处理。
- **本期策略**：前端保留「指令优化（Context-IR）」入口，但**本地实现为轻量提示词增强**（按官方提示词指南做规则/模板级优化），不作为 H3-Context-IR 官方等价物；不引入云 API 依赖。

### 6.5 2K 与云端边界

- 2K（H3-Regenerate-2K）未开源：本期不做本地 2K，前端「2K 重绘」选项置为不可用/提示需官方 API（占位，不实现云调用）。
- 模型来源：GitHub `MiniMax-AI/MiniMax-H3` / HuggingFace `MiniMaxAI/MiniMax-H3` / 魔搭 `MiniMax/MiniMax-H3`；国内下载优先魔搭。
- 许可证：MiniMax H3 Community License（再分发 / 商用 / 微调前需确认条款）。

## 7. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 生成结果反馈延迟 ≤1s（不含推理时间）；推理时长如实展示（估算与真实时长） |
| 并发 | 单机默认串行推理，可配置最大并发 1–2（显存受限） |
| 存储 | 结果视频落盘路径规范化；历史库容量提示（可选清理策略） |
| 可靠性 | 任务失败原因透传前端；断连可重查任务状态 |
| 安全 | 本地单机，无网络暴露面（默认仅 127.0.0.1） |
| 可访问性 | 键盘可达、aria 标注、对比度达标；设计质量 P0=0 |
| 兼容 | 明暗双主题、响应式（桌面 / 平板 / 手机） |

## 8. API 契约（草案）

```
POST   /api/projects                   新建项目
GET    /api/projects                   项目列表
GET    /api/projects/{id}              项目详情（含镜头）
PUT    /api/projects/{id}              重命名
DELETE /api/projects/{id}              删除项目（级联镜头/历史）

GET    /api/projects/{id}/shots        镜头列表
POST   /api/projects/{id}/shots        新增镜头
PUT    /api/shots/{sid}                更新镜头（提示词/参数/顺序）
DELETE /api/shots/{sid}                删除镜头

POST   /api/generations                提交生成任务（模式+提示词+参数+参考）
GET    /api/generations/{task_id}      查询任务状态（status/progress/error/result）
POST   /api/upload                     参考素材上传（返回 asset_id）

GET    /api/projects/{id}/history      项目历史（已完成镜头/结果）
GET    /assets/{asset_id}              结果视频 / 素材静态访问
```

> 参考素材依赖：多模态参考模式 / 首尾帧模式须先上传素材换取 asset_id。

## 9. 验收标准

1. 单项目内 N 镜头完整闭环：编排 → 生成 → 队列 → 结果回填 → 历史可看。
2. 多项目切换数据隔离，不串镜头 / 参数 / 历史。
3. 五模式参数与真实模型规格对齐（时长/比例/参考上限校验生效）。
4. 本地推理 768P 生成成功并回填舞台；失败有明确原因提示。
5. 明暗双主题、响应式、可访问性通过（设计质量 P0=0）。
6. 高保真升级完成：应用本项目强调色（随展示壳模式切换：剧场红 / 电视琉珀 / 放映机青绿），无线框 / 占位字样残留。

## 10. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| H3-Base 显存门槛（16G 长视频 OOM） | 生成长视频失败 | 量化档位配置 + 时长校验提示 |
| Context-IR / 2K 未开源 | 复杂指令质量与高分辨率受限 | 明确标注能力边界，提示词优化走本地轻量方案 |
| 本地推理耗时长（分钟级） | 体验 | 队列 + 真实进度展示 + 后台可继续操作 |
| 许可证合规 | 商用受限 | 落地前确认 Community License 条款 |
| 兄弟项目配置风格差异 | 维护成本 | 配置/脚本向兄弟项目对齐 |
